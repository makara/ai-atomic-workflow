# AI Atomic Workflow

Project glossary — term disambiguation only. Graph execution engine + skill system that turns architecture reviews and doc-estate changes into executed graph runs. This file is injected every session; keep entries to definition + invariant, refer details to cited sources (CR3 no-redundancy).

## Language

**Graph**: Declarative workflow graph definition in workflow YAML (`.yaml`) — directed graph of phases wired by `dependsOn` edges with control-flow fields (`flow` transition edges, ADR 0240); replaces skill call chains as orchestration description. Dependency edges acyclic by authoring rule (enforced at load, cycle path); runtime rework loops (flow self-edges — bounded transitions, never dependency edges) are declared in the top-level `flow` block.

**DAG**: Descriptor for a graph's dependency edges only. Never a name for the engine — its runtime transitions form bounded rework loops (JUMP closure, retryCount-capped).

**Atom**: Project-name vocabulary — the user-facing word for the graph's execution unit: **every node in a graph** (ADR 0183; former HLT registered tool call meaning retired — see HLT registered tool call). Each atom describable by a **bounded compound sentence**: connectors `and`/`then`/`if-else`/`OR`; ordinary nodes ≤ 5 steps; conditional paths ≤ 3 (graph.md R12; bounds convention, user-calibratable). Graphs carry an atom overview under the dedicated schema key `inventory` (R13 — never named "atom"; entries `{ id, type, goal, constraints? }`).

**Phase**: Execution unit in the graph — type set {main}: main → inline execution + decision (the only dispatch type); nested execution is `template: router` sibling runs (subgraph composition via `use` is deleted, ADR 0237). Human decisions are main-node inline interview() confirmations (approval node type removed, ADR 0215); rework/loop is declared as a flow self-edge and routed by the advance condition/jump channels (gate node type removed, ADR 0216; ADR 0240).

**Main type**: Phase type (ADR 0028 D1) executing the task inline in the main agent process. Handler skill = "atom-phase-handler" (builtin); execution skill = `phase.skill` (optional).

**Approval**: REMOVED as a phase type (ADR 0215) — was a human-decision phase with routing actions (continue/retry/jump/end; that branch-routing mechanism now lives on main — see Routing / Route). Human confirmation is now a single-form decision card via approval()/interview() on a main node; rework is expressed as main task-text rework decisions (backward resets), never approval routing.

**Gate**: REMOVED as a phase type (ADR 0216) — was a pure rework node evaluating `jumps` `[{when, to}]` conditions; rework/loop is now declared as a flow self-edge and applied mechanically on advance — the normal advance reports a `condition` value (matched against the flow transition table; no match fails loudly) and forced rework travels via the `jump` channel (target ⊆ topological ancestors ∪ `__handoff`; ADR 0240). `branchTo` is deleted (ADR 0238).

**Activation prologue**: REMOVED (ADR 0148) — no synthesized run nodes; activation facts live at the invocation boundary: `graph_start` takes no `mode` argument (run mode removed, ADR 0215); heavy startup steps are NOT activation steps — they run inside the graph's `template: startup` node when declared (ADR 0234; default bare). `$`-prefixed phase ids are schema-rejected.

**Entry node**: Plain main phase with `dependsOn: []` acquiring the journey scope (idea, report, plan metadata) — the graph's first author node after activation (or the first node after the `startup template` node when the graph declares full startup).

**Startup template**: Builtin task template (ADR 0232 mechanism, `src/task-templates/startup.ts` + `TASK_TEMPLATES`) referenced by a phase-level `template: startup` field on a graph's ENTRY node (mutually exclusive with `task`, empty `dependsOn` — schema-enforced; the `use` field no longer exists, ADR 0237; ADR 0234). The compiled-in task text runs the heavy startup steps once: project constraints session load (`.graph-scheduler/constraints.json` → session — every downstream node's `## Constraints` block is assembled from this session copy), serena `activate_project`, jcodemunch `index_folder`. Self-decide, no user questions.

**Bare startup**: The default graph startup mode — `graph_start` + execute→advance loop + tool detection only, no constraints load, no LSP activation, no indexing. Graphs needing the heavy steps declare `template: startup` (full startup). The pilot never runs the heavy steps on its own — only the declared template node does.

**Run mode**: REMOVED (ADR 0215) — was a per-activation decision (manual/auto) passed to `graph_start` as `args.mode` (required; absent → `MODE_REQUIRED`); per-activation mode selection no longer exists. Activation is user-driven by default; every decision renders as a card (see Decision UI / approval()).

**Ambient context**: Environment-supplied context assembled for every phase — convention files (`CONTEXT.md`, `docs/domains.md`, platform-shipped, absence-tolerant), user supplement (`.graph-scheduler/config.json` `context:`, existence-validated), platform estate (`docs/adr/**`, `openspec/**`, `CHANGELOG.md`, `README.md` — read organically, never declared), plus graph-declared channels. Effective ambient context = one deterministic merge, identical for every phase.

**Channel**: Context delivery edge — `skill:` references, `node:` stream promotions, file globs under workflow runtime artifacts — resolved from the skill's `## Context Requirements` contract and ambient sources. Delivered channel materializes as an assembled prompt block (`## Upstream:` / `## Reference:` / `## File:` sections prepended at dispatch).

**Context contract**: The skill's declaration of context needs — `## Context Requirements` four-subsection contract (From upstream / Reference skills / Operation classes / Files); consumed agent-side by the handler (engine never parses it — see Vocabulary correspondence).

**Entry-skill contract**: Callee-parameterized contract (ADR 0126) — arrives via the dispatching phase's task text (`Topics` / `Output contract` / `Behavior` flags); behavior = f(declared parameters), never caller identity; verified agent-side, engine holds no contract machinery.

**Route**: REMOVED (ADR 0221, syntax v2) — was route membership declared on main branch-route nodes / flow carriers; conditional routing is now declared as top-level `flow` edges (`A -->|condition| B` → transition table, ADR 0240) — the pilot reports the condition value on advance and the graph activates the matched target; unselected flow targets stay pending.

**Routing**: REMOVED (ADR 0221, syntax v2) — was the branch-route decision field (`routing.actions`, delivered as `routingActions`); conditional routing is now the flow transition table (top-level `flow` edges → node × condition → target; unlabeled edge = sequence default, ADR 0240). The advance carries the reported `condition` (normal advance — no match fails loudly) or a `jump` target (graph-internal forced rework, backward-only ∪ `__handoff`); the graph — never the pilot — decides the next node.

**Run state**: Scheduler-owned per-node execution facts — status, retryCount, timestamps (route mechanism deleted, ADR 0221). Progress only; node CONTENT lives in the agent session (platform-persisted transcript, ADR 0143).

**Output contract**: Declared field list a main phase emits — the report the node produces in its session (platform-persisted), consumed downstream via channels (ADR 0143).

**Completion**: Machine-declared decision options on the NodeDetail dispatch payload — `{ default, choices[], direct_end }` — derived at compile time from the flow transition table (the node's condition edges) and explicit `direct end:` declarations (ADR 0222; the `rework` field is deleted with branchTo, ADR 0238/0240). Consumers (pilot/handler) route decisions from this block and report the flow-defined `condition` value on advance; task-text branch parsing is removed from the dispatch path.

**condition**: `graph_advance` normal-advance parameter (ADR 0240) — reports the flow-defined condition value a node's execution produced; the value is a member of the flow edge-label vocabulary, defined by the top-level `flow` block and matched mechanically (string equality) against the reported node's outgoing edges. Matched → the edge's target activates; no match → loud error (missed-condition guard, never silent default); omitted → the sequence default activates. The pilot never picks a next node — the graph is the interpretation authority.

**Handoff**: Built-in special main node (NOT a new phase type — type set stays `{main}`, ADR 0216/0221) synthesized at graph compile time (ADR 0230, session contract per ADR 0233): every graph gains a single root `__handoff` (composition is deleted — no `<composing>/__handoff` exists, ADR 0237). Produces the unified two-element result report (see Result report) returned to the session; depends on the graph's terminals; rework resets include it (downstream terminal); unselected branches leave it pending. `$` prefix stays reserved, handoff ids use `__handoff`. The result-report wording is single-sourced in `task-templates/handoff.ts` (debt Card 15/23).

**Result report**: Unified two-element graph result report `{ 完成任务, 产出位置 }` produced by the synthesized handoff node — user-ruled minimum (ADR 0230; five-element skeleton was examples, not requirements). Facts with single sources (tickets via openspec change status, modified files, executed tests) are NOT re-accounted — reachable via the output pointer. Session-only (ADR 0233): the two elements are returned to the executing session — no report file, no deterministic path (ADR 0230 D3 revoked). `产出位置` follows the typed-pointer contract: file path (durable cross-run carrier for artifacts the run produced) / `agent://` / `artifact://` / `history://` (same-session).

**retryCount**: Single counter for node retries — JUMP increments it (never zeroed); rework conditions bound auto-rework against it (ADR 0046).

**Cross-run delegation**: SUPERSEDED (ADR 0233) — was the third execution-mode value on a composing `use` phase (`execution: cross-run`, ADR 0231); the whole mechanism (delegation node + DELEGATION_TASK + sibling-run launch + report collection) is removed with the composed execution surface. Historical: the composed subgraph's work executed as a SIBLING graph run launched by the frontend; hint semantics — refusal fell back inline; cross-run rework was forbidden.

**Sibling run**: ACTIVE (re-introduced by the router template, ADR 0236; sole nesting form per ADR 0237) — a graph run launched by the frontend at a `template: router` node: the chosen path's activation IS the sibling run (`graph_start` → drive to `node: null` → collect the handoff result via the router's report fields). The pilot drives all runs (single-driver rule). Historical: cross-run delegation sibling runs were removed with the composed execution surface (ADR 0233).

**Flow**: ACTIVE — the top-level `flow` field (ADR 0240): an array of mermaid-subset transition edges (`A -->|condition| B`; unlabeled = sequence default; self-edge = bounded loop) compiled into the transition table (node × condition → target) — the graph's conditional-routing authority, matched mechanically on advance via the `condition` channel. Loops are flow self-edges (inline bounded loops, invisible to the frontend); condition values are flow-defined (edge-label vocabulary, zero machine validation axis — inventory regime). Mermaid-format compliance (ADR 0242): the subset grammar is a strict subset of the mermaid flowchart grammar — builtin graphs are verified by the suite regression test (real mermaid parser); project graphs are verified at load time (a non-conformant block → load-time problem → `graph_assets`, never blocks the run). Historical: the former `Flow` (load-time composition via `use`, depth cap 5, ADR 0043) was deleted with subgraph composition (ADR 0237) — that meaning is superseded; nested execution is the `template: router` sibling run only, flow-orthogonal.

**Registry**: Graph registry (`graphs/registry.json`) — scenario name → graph file path. Builtin graphs (`packages/graph-scheduler/graphs/`) + project graphs (`.graph-scheduler/graphs/`) merged; same-name graphs: project overrides builtin. Registry entries are a pure index `{name, path}` — description lives at the graph definition top-level as the catalog single source, the tags axis is deleted (ADR 0235).

**Graph perception list**: System-level graph info list mirroring skills perception — the frontend-facing catalog of what graphs exist, what they do, and how they run, without reading graph files (ADR 0235). Content = the five-field `graph_assets` payload `{id, description, run_conditions, source, problems}` (graph-mcp-api spec): `description` single-sourced from the graph definition top-level, `run_conditions` projects the definition's `interaction` value + constraints presence (L-TRACE — never a new fact source), `source` = `builtin | project | fallback`. Form = compact resident block at pilot activation (one `id + description` line per graph, mirroring the skills `<skills>` block; detail on demand, failure degrades). Lifecycle = produce (single-source projection) / load (activation query + on-demand) / use (selection, run-condition awareness, problem surfacing). Invariant: projection only — the frontend never writes the list; freshness = disk read at query time, no in-memory graph cache (ADR 0188).

**Domain index**: `docs/domains.md` — fine-grained DDD domain standard + index (one domain per skill/graph/feature point); governs "who owns what"; glossary governs term disambiguation; no duplication.

**ADR**: Architectural decision record in `docs/adr/` — sequential numbering, status state machine (accepted/superseded/deprecated), fold-on-supersede to `docs/adr/archive/`.

**Spec**: OpenSpec delta specification (`openspec/specs/`) — requirements with scenarios, per-capability; changes propose deltas, archive syncs them into main specs.

**Change**: OpenSpec change proposal (`openspec/changes/<name>/`) — proposal + delta specs + design + tasks; apply implements, archive folds into main specs.

**Workflow YAML**: Graph definition format (`.yaml`) — `name`, `context`, `phases` with dependsOn/channels; validated at graph load (ADR 0049). Phase schema is strict — any unknown phase key (removed fields like `route`/`mode`, legacy fields like `topic`) is rejected at load with the key named, never silently stripped; graph-maintain's schema-unknown key audit cleans such graphs (ADR 0227).

**Constraint**: Graph behavior boundary, three layers: (1) **project** — rules in `.graph-scheduler/constraints.md` `## Rules`, LLM-compiled into `.graph-scheduler/constraints.json` (compiled-artifact protocol: existence = validity), loaded once into the session by the graph's `template: startup` node when declared (default bare — no load; ADR 0234), injected as `## Constraints` `[project]`-prefixed block on every downstream node (session copy — the startup template node itself dispatches without the block, it IS the loader); (2) **graph** — top-level `constraints` field (same level as `inventory`; self-containment, L-TRACE), read at dispatch, injected as `[graph]`-prefixed `NodeDetail.constraints` entries (unbypassable machine facts; composed graphs union subgraph constraints; dispatch-time snapshot — mid-run edits change later injections); (3) **entry** — inventory entry-level `constraints[]`, doc-only review surface, never injected. Delivered as prose policy clauses (followed + self-reported via Checks); no static TTSR rule file (deleted, ADR 0153 + 0154).

**Decision UI / approval()**: Platform decision primitive — single-form decision card per call; no mode dispatch (run mode removed, ADR 0215): every decision renders as a card, never auto-executed. Absorbs question().

**Interview()**: Confirmation primitive — multi-round consensus conversation confirming candidate decisions, with caller-declared `participation: 'mandatory' | 'as-needed'` (as-needed may converge when context covers the goal; mandatory always asks — never inferred). Turns via approval() without recommendation — always a card, never auto-skipped.

**Grilling**: Exploration primitive — design-tree frontier interrogation (upstream skill, mattpocock/skills, hash-locked — body never modified). Encapsulation contract in node task text: mandatory question rounds, whole frontier per round, never zero-question, never auto-gated; output shape `decisions` + `shared_understanding` — never `consensus`.

**Judge()**: REMOVED (ADR 0216) — was a one-shot lightweight-model judgment for gate jump-condition evaluation; rework conditions are now evaluated inline by the executing agent from main task text, so no separate judgment primitive exists.

**endRun**: REMOVED (ADR 0215) — was a `graph_advance` boolean param (`endRun: true`) completing the run immediately; `graph_advance` has no endRun — runs complete via natural drain only.

**Direct end**: Interview-layer explicit end capability — any main confirmation node may declare `direct end:` in task text; the final confirm card then offers two options (`nothing to adopt (recommended)` / the declared label, e.g. "end this round"), either SHALL end the round directly: the node report carries `direct_end: true` and the pilot advances with `end: true` (`graph_advance { runId, nodeId, end }`) — the run completes as `completed` without resuming the graph (ADR 0223), never `graph_force_end` (abnormal termination only). Generic contract: atom-kernel §interview(); entry wiring: atom-scope-interview. Complements `PCL` end/finish (graph-external operator control) and natural drain; no endRun parameter (ADR 0215).

**Tool Discipline**: Tool discipline delivery (ADR 0194/0200/0203/0204/0205/0206 + change hint-tool-context + hints-structure-simplify) — the graph-fidelity consumer module (`src/hints.ts` + `src/resident-data.ts`, formerly `src/texts.ts` + `src/core/`) ships the scenario-keyed hint blocks (closed set find/read/write/verify/run, single-line body-only posture — no title; review role-triggered, excluded) plus the consumer display-decision function (`HintDisplayFn` — the promoted tool→scenario extension table `PROMOTED_TOOL_MAP` is deleted; the fn judges compliance inline via its tool-name sets), consumed through the SDK unified scenario interface (`hints.use(config)` — classify/get/render, classification = platform-native rules + consumer map, native priority; classify returns `{scenario?, compliant}`); hints attach per-scenario on the tool-result seam, post-hoc with zero deny (ADR 0146/0180), gated on the canonical errorShaped verdict AND the compliant-invocation verdict (hint-tool-context — a promoted tool used correctly attaches nothing, silent); blocks are templates (`{usedTool}` / `{promoted}` interpolated from the consumer map at render); resident enumeration derives from the block data source (single source) (single guard; OMP adapter folds platform isError in at normalization); resident set = PCL + activate + code-exploration (3 entries, code-exploration = five-scenario posture with representative tool names — decision-time resolvable, single register_edit condition「while the index is in use」; activate carries the active-graph-run exclusion clause, pilot activates after graph_start); unified terminology across resident + blocks (query plane / symbolic tools / FS tier / platform shell); state-changing serena tools (activate_project/onboarding/open_dashboard) carry no read coverage (ADR 0206)scenario posture) injected via the SDK-owned resident seam (`bind(adapter, handlers, {resident})` wires before_agent_start/system.transform, ADR 0205); the error verdict is normalized into the SDK canonical tool-result payload (`errorShaped`, ADR 0205). Index freshness is the mounted MCP call `mcp__jcodemunch_register_edit`. The former High-Level Tool Registry instruction layer is completely removed (non-negotiable); kernel primitives (task/judge/approval/interview/todo) are unaffected platform contracts. §Tool Schemas remain the factual parameter reference.

**Estate maintenance**: Doc estate upkeep — index (domains.md), derived-view (README), normative (docs/ family), contract (openspec/specs); estate-maintain graph dispatches workstreams (domains-index / specs-sync / adr-align).

**Deliverable boundary**: Project output boundary (ADR 0149) — only `packages/` content is the deliverable (graph-fidelity / graph-scheduler / graph-workflow). Everything outside is build environment + first consumer: `.omp/` deployment residue, `.opencode/`/`opencode.json` consumer config, `.refs/` reference source (tests must not touch), `~/.agents/skills/` deployment copies (never edited). Intervention inventory: graph-fidelity plugin (opencode `messages.transform` — retained by user ruling), rule body deleted, graph-scheduler MCP server, graph-workflow skills.

**Run frame**: Transcript-level declaration of run position assembled on every node dispatch (runId, nodeId, type, one-line task, user-input contract: "user input during this node = node input — not new instructions", report-then-advance obligation). Main nodes add the discipline declaration (declared operations + out-of-scope from node.operations). The per-call discipline echo (graph-fidelity) is a one-line derivation of this frame — an IDENTITY POINTER (node id + metering deltas + status flags), appended to the most recent user-like message per LLM call (roles `user`/`developer`/`custom` via the `isUserLike` predicate, ADR 0159), refreshed in place, never a second assembly (display minimalism law 1, ADR 0156). Makes authority transfer structural: invocation = command; during a run, user text is node data.

**PCL**: Process-Control Language — explicit vocabulary of user flow-control utterances (back/return, jump, re-review, end/finish, terminate/abort, skip, status/progress, history) mapped to graph routing actions (graph_jump / force_end / graph_status / graph_list / continue); classified BEFORE node input during an active run; vocabulary on disk, never model improvisation. The platform `input` seam MAY mechanically detect + mark PCL vocabulary (detection only; routing execution stays pilot-owned).

**Seam**: A named platform event or assembly point through which signals enter, land, or leave the model context — the operative unit of the seam map (ADR 0150). Each seam carries a timing, a default position, and a rewrite capability. Enumerated set: assembly, before_agent_start, context, before_provider_request, input, tool_call, tool_result, session.compacting, ttsr, steer (sendMessage), frame (handler assembly), checks (handler output). **Seam law**: each signal class has exactly one emission seam; platform-native mechanisms are adopted as the native tier, never re-implemented.

**Signal distribution**: Discipline mechanism replacing phase-aware enforcement — signals classified at EMISSION time and managed through their lifecycle (ADR 0146, seam-map wording per ADR 0150). The **seam map**: every signal carries one coordinate — primary class C1 control > C2 frame > C3 instruction > C4 context (priority resolved at emission; reclassification: frame turns user text into node data, PCL turns user text into routing), seam, fidelity tier L0 verbatim (protection list — decisions, receipts, node outputs, write results, skill injection, task text) / L1 condensed / L2 mapped (pointers, on-demand restore) / L3 pruned (superseded, consumed, stale, orphaned). Native tier is the implementation of record (compaction suite, programmatic steer, getContextUsage); graph code never re-implements it. L3 mechanized: superseded/useless = native + graph-fidelity; consumed = graph-fidelity context-seam elision (consumed upstream output → L2 pointer at consumer node boundary, ADR 0155) + agent discipline; stale/orphaned = platform idle compaction + agent discipline. Zero denial: registered capability never restricted — deny covers redundant platform write paths only (ADR 0177 D5); built-in deny implementation removed (ADR 0180).

**Token lifecycle**: Lifecycle governance frame (ADR 0155) — every token passes birth (prompt face: what content in what style enters) → life/death (context face: selection, position, fidelity L0–L3, prune, archive) → measurement (feedback face: usage facts, audit, nudge, reward), closed by the feedback loop (message_end facts → budget/nudge → policy). Each face = prose tier (degraded baseline, always present) + mechanical tier (upgrade, graph-fidelity seams only). Prompts classified by usage frequency: P0 system-resident (every LLM call — mechanical system-prompt injection, `[resident]` block: PCL vocabulary + activate guidance + discipline line + Code Exploration Policy; install = resident, no session toggle) / P1 session-resident (platform instruction loading: AGENTS.md, instructions files) / P2 node-resident (per-dispatch: run frame, constraints block, checks) / P3 cold-read (skills, tool schemas). Resident prompts ride the system-prompt seam, never the user channel.

**Display minimalism**: Three display laws (ADR 0156) governing graph-fidelity feedback: (1) **single-line echo** — at most one injected feedback line per call, identity pointer + deltas, never copying frame facts, refreshed in place; (2) **single-source metering** — every fact has exactly one render point; Checks/final report reference, never copy; (3) **behavior-reward pairs** — every display has a consumer + timing + consequence; dead surfaces removed, ungated displays gated. Two delivery surfaces: `context` seam echo (model-side per-call signal) and node-boundary `sendMessage` custom message (`display: true`, operator-side per-node display, TUI-visible) — same `renderEchoLine` content, one renderer two channels. Display tiering: mechanical tier (seam-live) = the single echo line is the ONLY per-call feedback; prose tier (plugin absent) = minimal baseline (single-line Checks block, 3-line final report); degrade fail-safe in both directions.

**Atomic needs (R1–R5)**: The five first-principles context-governance needs (docs/reports/2026-08-11-arch-review-signal-concepts.md §4.1, cited in ADR 0148): R1 selection / R2 position / R3 boundary / R4 fidelity / R5 authority — each mapped to its mechanical seam; the needs are the why, not a parallel coordinate system. R6 (audit/self-reporting) is the ledger face of R3/R4 — reconciled, not a sixth need. Definition site stays the report; this entry is the citable reference.
