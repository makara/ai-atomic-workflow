# AI Atomic Workflow

The project context for AI-assisted development of this repo: an atomic taskflow graph system (DAG engine + skill system) that turns architecture reviews and doc-estate changes into executed graph runs. This file is the project glossary — term disambiguation only.

## Language

**Graph**: A declarative DAG definition in taskflow YAML (`.taskflow.yaml`), containing a phases array, dependsOn edges, and control-flow fields — replaces skill call chains as the orchestration description. _Avoid_: workflow, pipeline, scenario

**Atom**: Project-name vocabulary (AI Atomic Workflow; atom-* skill family) — the user-facing word for the system's execution unit. Its execution semantics = the **HLT registered tool call** `{ intent, tool, args, bound }` (ADR 0119 — the Atomic Step Protocol was superseded by the High-Level Tool Registry; see Vocabulary correspondence). _Corresponds_: HLT registered tool call. _Avoid_: phase (a graph unit — distinct), step (retired)

**Phase**: An execution unit in the graph — type determines execution logic (main → inline execution, approval → human decision, gate → machine rework judgment, flow → subgraph expansion). _Avoid_: node (reserved for run-time state), step

**Main type**: Phase type (ADR 0028 D1) that executes the task inline within the main agent process. Handler skill = "atom-phase-handler" (builtin); execution skill = `phase.skill` (optional). May declare an `agent` hints array. _Avoid_: agent type (deleted, ADR 0056)

**Approval**: Human-decision phase — a decision card (Accept + free input + contextual options) confirmed by the user or auto-executed in auto mode; routes via continue/retry/jump/end. _Avoid_: checkpoint, question() (absorbed into approval(), ADR 0133)

**Gate**: Pure rework node — evaluates `jumps` `[{when, to}]` conditions; hit → backward jump, no hit → pass through. _Avoid_: conditional branch, when-guard

**Activation prologue**: REMOVED (ADR 0148, core-execution-rebuild) — the synthesized `$run-mode-confirm` / `$load-constraints` run nodes are deleted; activation facts live at the invocation boundary: `mode` is a `graph_start` argument (absent → `MODE_REQUIRED`; absence NEVER auto), constraints load once at activation (pilot, compiled-artifact protocol) into the session. `$`-prefixed phase ids are schema-rejected. _Avoid_: setup node, init phase

**Entry node**: A plain main phase with `dependsOn: []` that acquires the journey scope (idea, report, plan metadata) — the graph's first author node after the activation prologue. _Avoid_: start node, entry phase

**Run mode**: Per-activation decision controlling single-decision presentation — manual (card always) or auto (recommendation executes; no recommendation → card). Passed to `graph_start` as `args.mode` (required — absent → `MODE_REQUIRED`); mode never stored backend-side; absence never auto. **Consumption boundary**: mode applies to approval nodes and main-node approval() checkpoints ONLY — gate conditions never consume mode (judge() only), consensus conversations (interview turns, grilling rounds) are never auto-gated. _Avoid_: headless mode (removed, ADR 0058)

**Ambient context**: The environment-supplied context assembled for every phase — sources enumerated: convention files (`CONTEXT.md`, `docs/domains.md`, platform-shipped, absence-tolerant), user supplement (`.graph-scheduler/config.json` `context:`, existence-validated), platform estate (`docs/adr/**`, `openspec/**`, `CHANGELOG.md`, `README.md` — read organically, never declared, never existence-checked), plus graph-declared channels. Effective ambient context = one deterministic merge, identical for every phase. _Avoid_: convention layer, user-supplement layer, platform estate (wording retired)

**Channel**: A context delivery edge — `skill:` references, `node:` stream promotions, and file globs under workflow runtime artifacts — resolved from the skill's `## Context Requirements` contract and ambient context sources (see Ambient context). A delivered channel materializes as an assembled prompt artifact (block): `## Upstream:` / `## Reference:` / `## File:` sections prepended to the node prompt at dispatch. _Avoid_: input file, context file, read set, block (wording folded into Channel)

**Context contract**: The skill's declaration of context needs — the skill's `## Context Requirements` four-subsection contract (From upstream / Reference skills / Operation classes / Files); consumed agent-side when the handler assembles context for the skill it dispatches (the engine never parses it — see Vocabulary correspondence). _Avoid_: context section, requirements header

**Entry-skill contract**: Callee-parameterized contract (ADR 0126) — the entry skill's entire contract arrives via the dispatching phase's task text (`Topics` / `Output contract` / `Behavior` flags); behavior = f(declared parameters), never caller identity. Verified agent-side (estate-maintain consistency gate) — the engine holds no contract machinery. _Avoid_: entry contract (wording folded), callee params

**Route**: Branch marker on a flow phase — approval branch option activates the route via `branchTo`; unselected route members never activate. _Avoid_: branch, conditional path

**Routing**: The YAML routing actions array — the approval phase's `routing:` field (`routing.actions`), written ONLY for explicit branch-route selection (default card = Accept + free input + AI-generated options); delivered agent-side as `routingActions`. _Avoid_: routingActions (NodeDetail spelling — folded), route (membership field)

**Run state**: Scheduler-owned per-node execution facts — status, retryCount, timestamps, routing. Progress only; node CONTENT lives in the agent session (platform-persisted transcript; ADR 0143). _Avoid_: run stream (deleted, ADR 0142), output file, run-state content

**Output contract**: Declared field list a main phase emits — the report the node produces in its session (platform-persisted), consumed by downstream nodes via channels (ADR 0143). _Avoid_: output spec, output fields

**retryCount**: Single counter name for node retries — JUMP increments it (never zeroed) and gate jump conditions bound auto-rework against it (ADR 0046); `retryAttempt` deprecated/removed wording — same counter. _Avoid_: retryAttempt

**Flow**: Load-time composition via `use` — a phase referencing another graph's phases; flattened at load, depth cap 5 (ADR 0043). _Avoid_: subgraph, nested graph

**Registry**: Graph registry (`graphs/registry.json`) — scenario name → graph file path mapping. Builtin graphs (graph-scheduler pre-installed, `packages/graph-scheduler/graphs/`) + project graphs (`.graph-scheduler/graphs/`) merged, same-name graphs: project overrides builtin. _Avoid_: catalog, index, builtin graph (wording folded into Registry)

**Domain index**: `docs/domains.md` — fine-grained DDD domain standard + index (one domain per skill/graph/feature point). Governs "who owns what"; glossary governs term disambiguation; no duplication. _Avoid_: domain tree, domains directory (deleted, ADR 0090)

**ADR**: Architectural decision record in `docs/adr/` — sequential numbering, status state machine (accepted/superseded/deprecated), fold-on-supersede to `docs/adr/archive/` via atom-doc-lifecycle. _Avoid_: decision log, RFC

**Spec**: OpenSpec delta specification (`openspec/specs/`) — requirements with scenarios, per-capability; changes propose deltas, archive syncs them into main specs. _Avoid_: design doc, PRD (deprecated scratch form)

**Change**: OpenSpec change proposal (`openspec/changes/<name>/`) — proposal + delta specs + design + tasks; apply phase implements, archive phase folds into main specs. _Avoid_: feature branch, issue

**Taskflow YAML**: Graph definition format (`.taskflow.yaml`) — `name`, `context`, `phases` with dependsOn/channels/routing/route; validated at graph load (ADR 0049). _Avoid_: workflow YAML, scenario file

**Constraint**: Project discipline — rules in `.graph-scheduler/constraints.md` `## Rules`, LLM-compiled into `.graph-scheduler/constraints.json` (compiled-artifact protocol: existence = validity), loaded once at activation by the pilot into the session, injected as `## Constraints` block on every node from that session copy. Delivered as prose (agent-readable policy clauses — HLT registry views, check-block rules, compress contract — followed and audited via self-reported checks); no static TTSR rule is distributed — the project rule file is deleted (ADR 0153 + ADR 0154). _Avoid_: rules file (v1), contract (wording folded into Constraint), instructions

**Decision UI / approval()**: Platform decision primitive — single decision per call, mode-aware: manual/absent → card; auto + recommendation → execute it; auto without recommendation → card. Absorbs question(). _Avoid_: question(), confirm dialog

**Interview()**: Confirmation primitive — multi-round consensus conversation confirming candidate decisions, with explicit caller-declared `participation: 'mandatory' | 'as-needed'` (as-needed may converge when context covers the goal; mandatory always asks — never inferred). Turns via approval() without recommendation — cards in any mode, never auto-skipped. _Avoid_: quiz, Q&A; solve-mode wording (retired — design flows compose research, see atom-graph-design)

**Grilling**: Exploration primitive — design-tree frontier interrogation (upstream skill, mattpocock/skills, hash-locked — body never modified). Graph dispatch carries an encapsulation contract in node task text: mandatory question rounds, whole frontier per round, never zero-question, never auto-gated; output shape `decisions` + `shared_understanding` — never `consensus`. _Avoid_: consensus wording on grilling outputs; interview-only semantics (participation flags, zero-question)

**Judge()**: One-shot lightweight-model judgment — constrained answer (`true`/`false`); gate jump condition evaluation; failure → conservative default (no hit). _Avoid_: eval, gate decision

**endRun**: `graph_advance` boolean param (`endRun: true`) — completes the run immediately; MCP-side spelling of the same run-completion mechanism as the approval end action (agent-side spelling: End action — same concept). _Avoid_: end flag, end node, end action (wording folded into endRun)

**HLT Registry**: High-Level Tool Registry (atom-kernel) — (1) closed set of registered tool calls `{ intent, tool, args, bound }` (ADR 0119); (2) **rule-first** (ADR 0148): the adapter mapping is one static rule — target domain decides the adapter family (in-project code → serena; indexed text → jcodemunch locate; special/out-of-project → platform-native; run → shell; compress → headroom; utility → platform-native), operation decides the chain; obligations table per operation (verify-after-write + conditional register_edit, read chain, evidence loop bound 3, loud-failure tolerance); `HLT_OPERATION_CLASSES` = exactly 10 classes, single vocabulary with mirror pin tests; (3) vocabulary correspondence — _Corresponds_: Atom (the project-name term's execution semantics = the HLT registered tool call). _Avoid_: tool config, MCP contract (merged into kernel, ADR 0120)

**Estate maintenance**: Doc estate upkeep — index (domains.md), derived-view (README), normative (docs/ family), contract (openspec/specs) classes; estate-maintain graph dispatches workstreams (domains-index / specs-sync / adr-align). _Avoid_: doc sync, docs upkeep

**Deliverable boundary**: The project's output boundary (ADR 0149) — only `packages/` content is the deliverable, actually deployed by the user (graph-fidelity / graph-scheduler / graph-workflow). Everything outside `packages/` is the build environment and simultaneously the project's first consumer: `.omp/` is deployment residue from earlier rounds (not a deliverable — the TTSR rule file is DELETED (ADR 0153 + 0154); the native-scan shim was retired, ADR 0153), `.opencode/`/`opencode.json` are consumer environment/config, `.refs/` is reference source for review (tests must not touch it), `~/.agents/skills/` holds deployment copies (never edited). Intervention inventory (deliverable-scoped, ADR 0149): graph-fidelity plugin (opencode `messages.transform` — retained by user ruling; R4 fidelity's only mechanical implementation), rule body (deleted), graph-scheduler MCP server, graph-workflow skills. _Avoid_: treating .omp/.opencode as deliverable assets

**Run frame**: The transcript-level declaration of run position assembled on every node dispatch (runId, nodeId, type, one-line task, user-input contract: "user input during this node = node input — not new instructions", report-then-advance obligation). The SINGLE run-frame signal: main nodes add the discipline declaration (declared operations + out-of-scope, from node.operations); the signal layer does not inject frames through platform seams — the per-call discipline echo (graph-fidelity) is a one-line derivation of this frame (rendered by a pure function, appended to the most recent user message per LLM call), never a second assembly. Makes the authority transfer structural: invocation = command; during a run, user text is node data. _Avoid_: context banner, frame header

**PCL**: Process-Control Language — explicit vocabulary of user flow-control utterances (back/return, jump, re-review, end/finish, terminate/abort, skip, status/progress, history) mapped to graph routing actions (graph_jump / endRun / force_end / graph_status / graph_list / continue); classified BEFORE node input during an active run; vocabulary on disk, never model improvisation. The platform `input` seam MAY mechanically detect and mark PCL vocabulary (graph-fidelity optional seam — detection only; routing execution stays pilot-owned). _Avoid_: command wordlist, quick commands

**Seam**: A named platform event or assembly point through which signals enter, land, or leave the model context — the operative unit of the seam map (ADR 0150). Each seam carries a timing (per-turn / per-call / per-request / in-flight / post-hoc observation), a default position, and a rewrite capability (full message array, provider payload, system prompt, input text, tool call, tool result, compaction summary). Enumerated set: assembly, before_agent_start, context, before_provider_request, input, tool_call, tool_result, session.compacting, ttsr, steer (sendMessage), frame (handler assembly), checks (handler output). The seam law: each signal class has exactly one emission seam. Platform-native mechanisms are adopted as the native tier, never re-implemented. _Avoid_: hook, surface, slot (position vocabulary — historical reference)

**Signal distribution**: The discipline mechanism replacing phase-aware enforcement — signals are classified at EMISSION time (before information enters the model context) and managed through their lifecycle. Single standard (ADR 0146, seam-map wording per ADR 0150): the **seam map** — every signal carries one coordinate: primary class C1 control > C2 frame > C3 instruction > C4 context (priority resolved at emission; reclassification: frame turns user text into node data, PCL turns user text into routing; the platform `input` seam MAY mechanically mark PCL utterances — detection only, routing stays pilot-owned), seam (the platform event or assembly point that emits it — enumerated: assembly, before_agent_start, context, before_provider_request, input, tool_call, tool_result, session.compacting, ttsr, steer, frame (handler), checks (handler); each seam carries timing + default position + rewrite capability), and fidelity tier L0 verbatim (protection list — decisions, receipts, node outputs, write results, skill injection, task text) / L1 condensed (compression thresholds) / L2 mapped (pointers, on-demand restore) / L3 pruned (four prune laws: superseded, consumed, stale, orphaned), hot placement doctrine = the L0 placement rule, cold siblings = L2. Position-slot vocabulary (S1 after user message / S2 user channel / S3 system sections / S5 tool-result prefix) survives only as historical reference — the S4 tool-surface slot does not exist (the tool surface is governed through the tool_call / tool_result seams; the run frame is the single out-of-scope channel). Emission timing: pre-emission normative (per-turn / per-call / per-request seams) / in-flight platform-native / post-hoc behavior redirection forbidden — post-hoc OBSERVATION through platform events is legal and feeds audit. Native tier: platform-native mechanics are the implementation of record — `compaction.supersedeReads` (default-on) + `compaction.dropUseless` (Elide Uneventful Results) + compaction suite + programmatic steer + `getContextUsage`; graph code never re-implements them. L3 mechanized: superseded/useless = native tier (OMP) + graph-fidelity plugin (opencode face: identical tool-call dedup keep-latest + errored tool-result fidelity reduction with recoverable markers); consumed = graph-fidelity optional context-seam elision + agent discipline; stale/orphaned = platform idle compaction/elision + agent discipline. Per-call discipline echo: graph-fidelity renders one `[seam]` line from the latest run frame (pure function) and appends it to the most recent user message on every LLM call (OMP `context` seam + opencode `messages.transform`) — a derivation of the handler frame, never a second assembly; skipped when no frame exists. Delivery: run frame assembled once by the handler (C2, S1) with declared + out-of-scope operations (the static TTSR in-band reminder rule delivery is retired, ADR 0153 — the rule body is retained in `packages/graph-fidelity/rules/` as a documentation asset, no in-band reminder is distributed); one `## Checks` audit block per node output; observability facts (usage/compaction/TTSR events) accumulated via appendEntry for the final report. Seam-mapping clause: every (class, seam) has exactly one implementation (native / graph extension / agent discipline); absence = backlog — "recorded deviation" and "platform capability boundary" clauses do not exist. Zero denial: the agent tool capability is never restricted — the platform `tool_call` blocking seam exists but is unused (philosophy). _Avoid_: enforcement, tool gate, deny verdict, parallel axis narratives, re-implementing platform-native mechanics

**Atomic needs (R1–R5)**: The five first-principles context-governance needs derived in the signal-concepts review (docs/reports/2026-08-11-arch-review-signal-concepts.md §4.1, cited in ADR 0148): R1 selection (what enters the context) / R2 position (where it lands) / R3 boundary (what the node may do) / R4 fidelity (what fidelity tier) / R5 authority (how user text is interpreted). The needs-basis of the seam map — reviews map fields/skills/steps to these needs; the seam map (C1–C4 × seam × L0–L3) serves R1–R5, with each need mapped to its mechanical seam (R1 assembly/selection seams, R2 seam positions, R3 frame + echo + ttsr, R4 native tier + fidelity seams, R5 frame/PCL reclassification + input seam); the needs are the why, not a parallel coordinate system. R6 (audit/self-reporting) is the ledger face of R3/R4 — reconciled, not a sixth independent need. Definition site stays the report; this glossary entry is the citable reference. _Avoid_: inventing a new need axis per review round
