# 设计哲学（P1–P5）

> **来源**：由 G1–G3 衍生出的五条设计哲学，指导具体规范的制定。定义于 `core/design-goals.md`。

| # | 哲学 | 核心原则 |
|---|------|---------|
| **P1** | **先做框架，再做内容** | Bootstrap 执行指引比具体产出更重要；没有框架的内容无法追溯和复用。 |
| **P2** | **显式胜于隐式** | 约束必须显式记录；计划草案必须落盘才算存在；对话中的内容视为不存在。 |
| **P3** | **用户主导，AI 辅助** | 用户的每次确认都是不可绕过的门控；"没有反对"不等于批准。 |
| **P4** | **渐进式承诺** | 先做小决策，再做大决策；第一步不需要确定所有细节；大范围返工是设计缺陷信号。 |
| **P5** | **最小化 Context 加载** | 精确的 context 比丰富的 context 更有价值；宁可多次加载，也不要一次预取所有材料。 |
| **P6** | **基于完善的开源工具** | 优先复用业界成熟的开源工具和技能体系（如 mattpocock/skills），不做重复建设；自有实现仅针对明确未被现有工具覆盖的缺口。 |
